# معايرة محرّك جودة المحتوى

> **سياسة القبول:** لا يصبح المنشور "approved" بسبب متوسط مرتفع أو ادعاء النموذج بالموافقة. يجب أن يجتاز كل بُعد حرج حدّه، وأن يقدّم دليلًا وسببًا وإصلاحًا مقترحًا، وألا توجد مشكلة حرجة أو فشل في الحراس الحتمية.

## سلالم الدرجات

| النطاق | التفسير | أثره التشغيلي |
|---:|---|---|
| 0–49 | مكسور أو غير آمن | يُرفض ويحتاج إعادة كتابة جوهرية. |
| 50–69 | ضعيف جوهريًا | يُرفض؛ لا يصلح تحسين سطحي. |
| 70–84 | مسودة قابلة للتحسين | يُرفض من النشر ويُعاد إلى حلقة التحسين. |
| 85–89 | قوي لكنه غير جاهز للنشر | يُرفض من النشر حتى يصل إلى حد البُعد المطلوب. |
| 90–94 | جاهز للنشر | يمكنه عبور البوابة إذا اجتاز جميع الأبعاد والأدلة. |
| 95–100 | استثنائي | نتيجة ممتازة لكنها لا تعفي بقية البوابات. |

## الأبعاد والحدود

| البُعد | الحد الأدنى | الهدف من البوابة |
|---|---:|---|
| تحقيق الهدف | 85 | يثبت أن النص يخدم الطلب بدل إنتاج نص عام. |
| ملاءمة الجمهور | 85 | يحدّ من المخاطبة العامة وغير الموجّهة. |
| التوافق مع البراند | 90 | يحمي الهوية والنبرة والقيم. |
| ملاءمة المنصة | 90 | يضمن البنية والطول والصياغة المناسبة. |
| جودة اللغة | 90 | يمنع النص غير الطبيعي أو الركيك. |
| الوضوح | 85 | يمنع التشتت والتناقض وفقدان الفكرة. |
| سهولة القراءة | 85 | يفرض تنظيمًا قابلًا للمسح والفهم. |
| قوة البداية | 80 | يرفض الافتتاحيات الضعيفة أو النمطية. |
| القيمة | 85 | يمنع الحشو والنصوص التي لا تقدم فائدة. |
| الدعوة للإجراء | 75 | يضمن إجراءً مناسبًا دون إفراط بيعي. |
| الأصالة | 80 | يقلل التكرار والقوالب الجاهزة. |
| صحة الادعاءات | 90 | يحمي من الحقائق غير المدعومة أو المضللة. |
| سلامة المحتوى | 95 | يمنع النص غير المهني أو غير الآمن أو الحساس بلا حماية. |

تظل الدرجات الكلية، وجودة العربية، وملاءمة LinkedIn عند استهدافه، وملاءمة البراند هي بوابات متوافقة مع العقد السابق بحد **90**. أي قيمة مفقودة، أو دليل مفقود، أو `critical_issues` غير فارغ يؤدي إلى الرفض.

## عقد الأدلة وحلقة التحسين

يتطلب `dimension_evidence` عنصرًا لكل بُعد، يضم اسم البُعد ودرجته وسبب التقييم ومقتطفًا أو أكثر من النص وإصلاحًا محددًا قابلًا للتنفيذ. تُعاد هذه العناصر إلى Rewrite Agent؛ لذلك يطلب من الكاتب إصلاح السبب المحدد بدل إعادة إنتاج منشور جديد عشوائيًا. لا يُبنى `Quality Proof` ولا يُعاد استخدامه إلا إذا كان كاملاً ومربوطًا بـ SHA-256 للنص ذاته.

## تحقق المعايرة

ينفذ `npm test` الحراس القائمة واختبار `qualityCalibration.test.ts`. يغطي الاختبار عشر حالات خصومية: hook ضعيف، تجاهل الجمهور، ادعاء واقعي غير مدعوم، CTA غير عملي، نص نمطي مكرر، لغة ضعيفة، عدم ملاءمة المنصة، مخالفة البراند، نص غير آمن، ونص غير واضح. كما يثبت قبول حالة قوية ذات أدلة ورفض الدرجات العالية عندما تكون الأدلة غائبة.
